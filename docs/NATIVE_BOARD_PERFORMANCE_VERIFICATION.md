# Native board performance

## Baseline recorded November 15, 2026

This is the predecessor baseline for the approved native-board optimization. Production optimization is still pending. Application source `838cb4844e43cc7a4a91fd806ed344aa3510e386` was frozen before measurement. The harness checkpoints are `4de2de7` (initial matrix) and `dd5eac1` (persistent failure markers). The [raw archive](evidence/native-board-baseline.json) includes source/harness revisions, artifact digest, dirty-tree flag, all emitted results, failed phases, DOM/resource diagnostics and errors.

Chromium 151.0.7922.34, Windows, 1584 × 1024, temporary synthetic profiles. Five samples per successful size/mode; serial execution, no retries. Every successful case verifies complete native reference identity count, chat/image/task readiness, an actual editable note, durable canonical save, and camera movement for canvas/mixed. Connector models are counted by unique ID: the installed native layer lists each twice, and the archive retains both raw entries and IDs.

Editor readiness is milliseconds, median [min–max]. It includes canonical loading, local module import, projection and rendering; it is not isolated projection CPU time. Fixture setup and fresh-document startup are separately recorded. Browser/OS cache state is not controlled.

These successful large cases are slow: recorded main-thread long-task totals at 500 references had medians of 62.9 seconds (document) and 96.5 seconds (canvas). Completion is not a smooth-interaction claim. Heap values are point-in-time main-thread diagnostics and exclude workers. Read counters count requests, not returned rows; visible image/editor counts are distinct from complete model counts. Cancel/retry preparation and bounded content hydration are subsequent work.

With a fixed **50-reference canvas**, five cases each passed in libraries containing 1k/10k/50k additional unrelated objects. Editor-readiness medians were 2716 [2493–3334], 3420 [2683–3833], and 3298 [2747–4309] ms respectively. Fixture data also includes message/page-owner objects. Large setup costs and end-to-end outliers remain in the archive; these results do not certify 50k editable native cards.

The combined evidence contains **55 passing attempts and five failing attempts**. The initial matrix was stopped after two 500/mixed failures exposed a harness bug: Playwright restarts workers after failure, which erased an in-memory skip marker. One active case was interrupted and two later repetitions were never started. A failing/passing regression now verifies persistent markers across worker processes. The resumed run correctly skipped the twelve later repetitions after its three 1,000-card failures, and passed all fifteen fixed-card library cases. Do not describe this as a 75/75 pass or discard the repeated failures.

The supervisor owns one child process and one generated profile per case. Deadlines include teardown. A hung case stops only that owned process tree; a separate live child survives the timeout regression. A reported result followed by hung cleanup is still a failure. Partial completed-phase metrics survive timeouts. The manually interrupted run's verified profile was removed after its browser descendants exited.

Harness verification: lint, formatting, both type checks and **247 source tests passed**. The production build passed at 41.42 MB. Preliminary 50-card all-mode diagnostics passed 3/3 after correcting test initialization/selection and unique connector counting; earlier diagnostic failures are retained locally. No application optimization or fresh whole-stage review is claimed by this baseline.

## Indexed projection planning — November 16 checkpoint

Native page planning now builds identity maps, resolves group collapse with iterative memoized ancestry, and groups direct placement children in one pass. Placement order/ties, geometry, shared entity references and offscreen connector endpoints are preserved. Cycles and missing ancestry report explicit errors before allocating the native collection. Existing unavailable connector endpoints are skipped as before.

Three new regressions failed for the missing planner, then passed; they cover ordered geometry, immutable snapshots, shared identity, nested collapse, damaged ancestry and 10,000 nested groups without recursion. Full lint/format/type checks and **250 source tests** passed; the production build succeeded at 41.42 MB. All **13 focused native/Brain/recovery browser cases** subsequently passed without retries. This is a focused group, not the full release browser suite.

The [isolated planning comparison](evidence/native-projection-planning.json) uses 1,000 placements and 500 nested groups, five serial old-then-new pairs. Predecessor ancestry/child scans took 1134–1181 ms; the new planner took 1.08–3.28 ms and returned identical collapse/children results. This synthetic test does not measure full native rendering or demonstrate usable 1,000-card editing. Cooperative construction and content hydration are still pending.

Browser verification retained failed runs: the first group passed 7/13, with five context-shutdown timeouts and a drag persistence expectation failure. An unchanged rerun passed 12/13, with a bend-count mismatch after Undo. Exact drag comparisons passed 3/3 on each build; connector comparisons passed 3/3 predecessor and 2/3 current profiles, followed by 3/3 current pointer diagnostics. No production drag/Undo fix is claimed. The trace showed no separate saved bend drag before Undo; diagnostics also observed pane/native-offset transitions. The harness now waits for acknowledged bend creation and stable current pointer bounds/offsets, and explicitly verifies a changed saved bend before Undo. Original endpoint, persistence, Undo and recovery assertions/timeouts remain; temporary diagnostics were removed. The final 13/13 result uses this stronger setup. Earlier intermittent gesture/shutdown failures remain recorded risks for final-stage verification.

## Cooperative preparation — November 16 checkpoint

The complete transient native page is now constructed in batches of at most 50 model operations. Preparation reports progress, disables editing, and supports cancellation and fresh-snapshot retry. Ownership covers partial documents, collections, panes, listeners and adapter sessions, including cancellation while a native render promise is pending. Only owned panes are removed, so abandoned work cannot clear a replacement workspace. Actual editing/navigation retains the existing flush and recovery guards.

The adapter also filters identical viewport notifications. Browser command tracing exposed a separate initialization issue: native note auto-height was publishing content-measurement changes as user card resizing. A small subclass of the installed native note view now honors canonical card dimensions and scrolls its complete content. Native controllers and geometry commands are retained; no object content is copied to another database.

Six new source regressions cover exact batch sizes, cancellation, late allocation, failure cleanup, idempotent disposal and viewport command filtering. Full lint/format/type checks and **256 source tests passed**, followed sequentially by a successful 41.43 MB production build. All **13 focused browser cases passed without retries**, including native drag/routing/Undo, three-mode editing, conflict navigation and recovery. In each mode a 1,000-reference preparation is cancelled, canonical placements are independently reduced to 50, then Retry reads that fresh complete snapshot. All 50 native identities/dimensions remain exact; cancellation and retry create no draft, revision or activity records. This demonstrates cancellation and retry correctness, not usable 1,000-card editing.

Failed verification attempts remain recorded: duplicate viewport filtering alone left the canvas/mixed journal regression failing; command tracing identified native auto-height, after which the dimension adapter resolved it. One integration attempt incorrectly registered an existing native service rather than overriding it. A fixture assertion used the wrong helper field. Sandbox process termination failed two harness tests; their exact synthetic children were verified/stopped and the approved-capability full source run passed. A browser run overlapped the source script that replaces `dist`; it failed navigation before app execution and was stopped. The final source → build → browser run used unchanged production artifacts throughout. Lazy content loading and final native-capacity acceptance remain pending.

## Visible and pinned content — November 16 checkpoint

The native page still contains every canonical reference, note, group and connector. Expensive rich text, conversation display, task data and local assets now load through a page-owned coordinator when visible or needed by selection, focus, dragging or unsaved drafts. At most four initial loads run together, including requests cancelled while their underlying read is still pending. Document references share one visibility observer per pane; canvas bounds use the installed point-center/zoom API with 200 screen pixels of overscan. Card movement refreshes visibility without replacing the editor.

Lightweight shells retain canonical IDs and titles. Their one page-scoped subscription reads only referenced entity IDs in batches of 100, immediately projects shell fields and never queries messages or assets. Hydrated content retains complete message order and existing rich editing, task and memory controls. Dirty resources retain the actual editor/DOM across native disconnect/reconnect and release after save/reconciliation when no longer needed. Clean collapsed shells keep Inspect/Graph/AI actions without creating hidden body editors. Duplicate, backup, history and reference operations continue to use complete canonical data.

All **273 source tests passed**; affected type checks, full lint/format and the 41.44 MB production build passed. The final **eight windowing browser tests passed without retries**: document/canvas/mixed deferral, exact dirty editor-node retention and saved reload, pan-to-load/unload, same-count cross-tab Inspector updates without camera/editor replacement, all five fixture connector IDs, reviewed offscreen conflict recovery, stable native editing-decoration height, and collapsed quick actions without hidden rich editors. All 50 fixture models remain represented. Earlier broader native/Brain/preparation/recovery runs also exercised existing behavior; the full release suite and repeated capacity measurements remain pending.

The frozen predecessor failed all four original windowing cases as intended: it hydrated offscreen rich text in all three modes and replaced the dirty rich-text node on native reconnect. Additional failure evidence found and fixed visibility not refreshing after movement, a resource leak when attachment throws, scheduled reads starting after disposal, hidden body loading for a collapsed selection, and missing collapsed actions. Entering native edit mode also exposed a mask-measurement feedback loop (220→260→300…660 pixels over twelve frames); the adapter now constrains mask measurement to canonical bounds.

Two camera-test setup issues are distinguished from application fixes: raw IndexedDB writes bypassed canonical Dexie notifications, so the test now uses a real second-tab Inspector save; it also waits for Fit's intentional remount before capturing identity. A later attempt passed app assertions but timed out during browser teardown. The final run closes its auxiliary owned tab through guarded desktop navigation and passes normal teardown with the original timeouts. Earlier failed runs remain recorded; no native-capacity claim is inferred from these 50-card correctness tests.
